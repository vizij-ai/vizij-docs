# CODE\_ORGANIZATION.md

## Overview

**Vizij** — “A Web Based Framework for Rendered Robot Faces” — is built as a modular MVC system:

* **Model**: schema + types used by controllers and the renderer
* **View**: web canvas/WebGL renderer
* **Controllers**: animation player, node graph (and future blackboard, behavior tree, image node)
* **Bridges**: WASM bindings and React helpers that connect controllers to web apps

We use a **hybrid topology**:

* **`vizij-web`** (npm workspaces): all web packages & apps (website + demos)
* **`vizij-rs`** (Cargo workspace): all Rust crates (engine-agnostic core logic, Bevy plugins, and WASM FFI)

This gives you fast iteration in each world, clear boundaries, and easy reuse.

---

## Repositories

### `vizij-web` (npm workspaces)

```
vizij-web/
  package.json             # workspaces + scripts
  scripts/
    build-wasm.mjs         # absolute-path wasm-pack build helper
  packages/
    @vizij/animation-wasm/   # npm wrapper around wasm-pack output (pkg/)
      pkg/                    # generated by wasm-pack (don’t commit)
      src/index.ts            # stable JS/TS API that re-exports from pkg
    @vizij/animation-react/  # React provider + hooks over the wasm API
    # (later) @vizij/node-graph-wasm, @vizij/node-graph-react
    # (later) @vizij/model, @vizij/react-model, @vizij/view-canvas, @vizij/controller-bridge
  apps/
    demo-animation/         # demo app using @vizij/animation-react
    # (later) demo-node-graph/, website/
```

**Why wrapper packages?**
They give external apps a stable import path and let you add helpers (version checks, lazy init) without exposing wasm-pack’s file layout.

---

### `vizij-rs` (Cargo workspace)

```
vizij-rs/
  Cargo.toml                # [workspace], shared lints/MSRV
  crates/
    animation/
      vizij-animation-core/     # pure Rust logic (engine-agnostic)
      bevy_vizij_animation/     # Bevy plugin wrapper around core
      vizij-animation-wasm/     # wasm-bindgen FFI (cdylib)
    node-graph/
      vizij-node-graph-core/    # (later)
      bevy_vizij_node_graph/    # (later)
      vizij-node-graph-wasm/    # (later)
    # future:
    # blackboard/, behavior-tree/, image-node/, etc.
```

**Naming conventions**

* Engine-agnostic crates: `vizij-<thing>-core`
* Bevy plugins: `bevy_vizij_<thing>` (familiar to Bevy users)
* WASM FFI crates: `vizij-<thing>-wasm` (exports a tiny JS API)

---

## Layering & Responsibilities

* **Core** (`*-core`): logic + state; easy unit tests; no wasm/no bevy.
* **Bevy plugin** (`bevy_vizij_*`): systems/resources to run the core in Bevy; can be consumed natively.
* **FFI** (`*-wasm`): `wasm-bindgen` boundary that exposes a *stable* JS surface (e.g., `new()`, `update(dt, inputs)`, `set_*`).
* **npm wrapper** (`@vizij/*-wasm`): stable ESM entry; re-exports wasm-pack `pkg/` and adds types/helpers.
* **React wrapper** (`@vizij/*-react`): Provider + hooks; optional Worker-backed runtime later.
* **Apps**: demos & website; only depend on the React (or wasm) wrappers, not raw `pkg/`.

---

## Versioning & Publishing (high level)

* **npm**: each package is versioned independently; publish with provenance from CI.
* **crates.io**: publish core first, then the Bevy plugin (ensure the plugin depends on core with both `version` + `path`).

---

## Future growth

* Add new controllers by copying the animation player pattern (core → plugin → wasm → wrappers).
* Add an **orchestrator** Bevy plugin if you want multiple controllers to coordinate.
* Optionally provide a **combined** WASM module that bundles multiple controllers for the website.

# DEVELOPMENT\_STRATEGY.md

## Goals

* Iterate quickly on controller logic without breaking web apps.
* Keep a **small, stable JS API** at the WASM boundary.
* Maintain clear layers so each part can evolve or be reused (even outside Vizij).

---

## Day-to-day: developing a controller (e.g., animation player)

1. Work in Rust first (`vizij-rs`):

```bash
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test --all-features --all-targets
```

2. Build WASM into the web wrapper:

```bash
cd vizij-web
npm run build:wasm
```

3. Demo it live:

```bash
npm i
npm run --workspace demo-animation dev
```

> Rebuild WASM when Rust changes (`npm run build:wasm`) and refresh. You can automate rebuilds with `cargo-watch` or a `wasm-pack --watch` flow if available.

---

## Day-to-day: developing website/React

* Ensure `pkg/` exists at least once:

  ```bash
  npm run build:wasm
  ```
* Change only TS/React? Just rebuild the wrappers:

  ```bash
  npm run --workspace @vizij/animation-wasm build
  npm run --workspace @vizij/animation-react build
  npm run --workspace demo-animation dev
  ```

Keep apps importing **`@vizij/*-react`** (or `@vizij/*-wasm`) — never the `pkg/` path directly.

---

## When to split things out

* Start together (monorepo/workspace).
* If a package/crate becomes broadly useful beyond Vizij, **extract it with history**:

  * `git filter-repo` or `git subtree` on the package/crate path
  * Transfer ownership on npm/crates.io; deprecate old package name if you rename
  * Leave breadcrumbs in READMEs

---

## External consumption modes

* **React**: `@vizij/animation-react` → `<AnimationProvider/>` + `useAnimation()`
* **Vanilla/other framework**: `@vizij/animation-wasm` → `await init(); new Animation(...)`
* **Native Bevy**: `bevy_vizij_animation` plugin

# DEVELOPMENT\_PATTERNS.md

## The FFI boundary (Rust ⇄ JS)

Design a **minimal, stable API** in `*-wasm`:

```rust
#[wasm_bindgen]
pub struct Animation { /* holds engine state */ }

#[wasm_bindgen]
impl Animation {
  #[wasm_bindgen(constructor)]
  pub fn new(config: JsValue) -> Result<Animation, JsError>;

  #[wasm_bindgen]
  pub fn update(&mut self, dt: f32, inputs: JsValue) -> Result<JsValue, JsError>;

  #[wasm_bindgen(js_name = set_frequency)]
  pub fn set_frequency(&mut self, hz: f32);
}

#[wasm_bindgen]
pub fn abi_version() -> String;
```

**Conventions**

* Use `serde_wasm_bindgen` for config/inputs/outputs.
* Map errors to `JsError`. Never panic across the boundary.
* Keep per-frame data small; later, for heavy streams, add **TypedArray** methods.

---

## React wrappers

Provide **Provider + hooks** with lazy WASM init and an rAF loop:

```tsx
<AnimationProvider frequencyHz={1}>
  <Panel/>
</AnimationProvider>
```

* Encapsulate the timing loop and state.
* Optionally provide a Worker-backed provider when you need main-thread relief (transfer typed arrays for throughput).

---

## Bevy plugin pattern

* Wrap your core logic in `Plugin` implementations (e.g., `VizijAnimationPlugin`).
* Expose clean resources/events for inputs/outputs so multiple plugins can compose.
* If multiple controllers must coordinate, add a thin **orchestrator plugin** that manages shared timing, events, or a “blackboard.”

---

## Build outputs & source control

* **Do not commit** `pkg/` (wasm-pack output). Generate it in builds and publish it inside the npm package via `"files": ["pkg", ...]`.
* Keep wrapper packages **small**: re-export `pkg`, add types, add version checks.

---

## Versioning & compatibility

* Add `abi_version()` in WASM; the wrapper or React provider can assert compatibility at runtime.
* For crates, follow SemVer; publish core first, then dependent plugins.

---

## Adding a new controller (template)

1. `vizij-rs/crates/<ctrl>/vizij-<ctrl>-core/` — logic & types
2. `vizij-rs/crates/<ctrl>/bevy_vizij_<ctrl>/` — Bevy plugin
3. `vizij-rs/crates/<ctrl>/vizij-<ctrl>-wasm/` — FFI crate
4. `vizij-web/packages/@vizij/<ctrl>-wasm/` — npm wrapper
5. `vizij-web/packages/@vizij/<ctrl>-react/` — React provider/hooks
6. `vizij-web/apps/demo-<ctrl>/` — demo app

Copy the animation player as a starting point; adjust names and config.

---

## Performance notes (when you need them)

* Run controllers in a **Web Worker** once per-frame work grows.
* Use transferable **TypedArrays** for high-rate data.
* WASM threads require COOP/COEP headers and special builds; start single-threaded and measure first.

---

## Troubleshooting patterns

* **npm EUNSUPPORTEDPROTOCOL**: replace `workspace:*` with semver (`^0.1.0`) or `file:` ranges.
* **Missing `../pkg/...`**: run `npm run build:wasm` *before* building wrappers/apps.
* **`wasm-pack` puts pkg in wrong place**: use the absolute-path `build-wasm.mjs`.
* **TypeScript fails before `pkg/` exists**: add a local `shims.d.ts` for the generated module (dev only).

## npm workspaces build order (root scripts)

`vizij-web/package.json`:

```json
{
  "workspaces": ["packages/*/*", "apps/*"],
  "scripts": {
    "build:wasm": "node scripts/build-wasm.mjs",
    "build:wrapper": "npm run --workspace @vizij/animation-wasm build",
    "build:react":   "npm run --workspace @vizij/animation-react build",
    "build:apps":    "npm run --workspace demo-animation build",
    "build": "npm run build:wasm && npm run build:wrapper && npm run build:react && npm run build:apps",
    "dev":   "npm run build:wasm && npm run build:wrapper && npm run --workspace demo-animation dev"
  }
}
```

`vizij-web/scripts/build-wasm.mjs` (absolute paths so `pkg/` lands in the right place):

```js
import { execSync } from "node:child_process";
import { resolve } from "node:path";

const crate = resolve(process.cwd(), "../vizij-rs/crates/animation/vizij-animation-wasm");
const outDir = resolve(process.cwd(), "packages/@vizij/animation-wasm/pkg");

execSync(
  `wasm-pack build "${crate}" --target web --out-dir "${outDir}" --release`,
  { stdio: "inherit" }
);
```

*(One-time: if `pkg/` was accidentally created inside the crate, delete `vizij-rs/crates/animation/vizij-animation-wasm/packages/`.)*

## Publishing

### Publish npm packages (from `vizij-web`)

**Prereqs**

* Secrets: `NPM_TOKEN`
* Each package has updated `"version"`, and wrapper lists `"files": ["dist","pkg","README.md"]`

**CI workflow (manual or tag)**

* Build wasm → build packages → `npm publish --access public --provenance` for:

  * `packages/@vizij/animation-wasm`
  * `packages/@vizij/animation-react`

**Local (if you prefer)**

```bash
npm run build:wasm
npm ci
npm run --workspace @vizij/animation-wasm build && (cd packages/@vizij/animation-wasm && npm publish --access public)
npm run --workspace @vizij/animation-react  build && (cd packages/@vizij/animation-react  && npm publish --access public)
```

---

### Publish crates (from `vizij-rs`)

**Prereqs**

* Secret: `CARGO_REGISTRY_TOKEN`
* `bevy_vizij_animation` depends on core with **version + path**:

  ```toml
  vizij-animation-core = { version = "0.1", path = "../vizij-animation-core" }
  ```

**Order**

```bash
cargo publish -p vizij-animation-core
sleep 20
cargo publish -p bevy_vizij_animation
```

*(CI workflow can run exactly those steps.)*
